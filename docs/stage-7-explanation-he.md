# שלב 7 - jQuery, Ajax ו-CSS3

## מה הוספנו בשלב הזה?

בשלב זה השלמנו שתי דרישות מפורשות של המטלה:

1. שימוש נרחב ב-jQuery, כולל קריאות Ajax לשרת.
2. שימוש בחמש יכולות CSS3: `text-shadow`, `transition`, `multiple-columns`,
   `font-face` ו-`border-radius`.

## שכבת ה-Ajax

הקובץ `client/src/services/api.js` הוא נקודת התקשורת המשותפת של כל ה-Views.
במקום שכל עמוד יגדיר קריאה אחרת, המתודות `get`, `post`, `put`, `patch` ו-
`delete` מפעילות פונקציית `request` אחת.

הפונקציה מפעילה `$.ajax` ומטפלת בנושאים הבאים:

- בניית כתובת ה-API.
- הוספת JWT לכותרת `Authorization` כאשר המשתמש מחובר.
- שליחת פרמטרים בשאילתת GET.
- המרת גוף של POST, PUT, PATCH או DELETE ל-JSON.
- הגבלת זמן ההמתנה לשרת לעשר שניות.
- המרת `done` ו-`fail` של jQuery ל-Promise שאפשר להפעיל עם `await`.
- שמירה על הודעת השגיאה שהשרת מחזיר כדי להציג אותה למשתמש.

בגלל שכל העמודים משתמשים בשירות המשותף, jQuery Ajax משתתף בפועל בהרשמה,
בהתחברות, בפרופיל, בחיפוש עסקים, בפוסטים, בתורים, בהיסטוריית הצ'אט
ובסטטיסטיקה. זהו שימוש רחב ולא דוגמה מבודדת.

## שימוש ב-jQuery בתוך ה-Views

ה-hook בשם `useJQueryReveal` מדגים גם בחירה ושינוי של רכיבי DOM באמצעות
jQuery. לאחר ש-React מציג כרטיסים שהגיעו מהשרת, ה-hook מוצא רק את הרכיבים
המסומנים ב-`data-jquery-reveal`, מוסיף להם מחלקות CSS ומציג אותם בהדרגה.

השימוש מופיע בארבעה מסכים:

- רשימת העסקים.
- רשימת הפוסטים.
- רשימת התורים.
- כרטיסי הסטטיסטיקה והגרפים.

חשוב להסביר בהגנה שה-jQuery מוגבל ל-container שמתקבל באמצעות `ref`. הוא לא
יוצר ולא מוחק רכיבים, משום ש-React אחראי על מבנה ה-DOM. כך נמנעת התנגשות בין
jQuery לבין ה-Virtual DOM.

## יכולות CSS3

בקובץ `client/src/styles.css` ניתן למצוא:

- `@font-face` המגדיר את הגופן `EasyBusy Local`.
- `text-shadow` בכותרות הראשיות.
- `transition` בכפתורים, בלוגו ובאפקט הופעת הכרטיסים.
- `column-count`, `column-gap` ו-`column-rule` באזור ההסבר בדף הבית.
- `border-radius` בכרטיסים, בכפתורים, בתגים ובאזור העמודות.

אזור העמודות גם רספונסיבי: במסך רחב הוא מוצג בשלוש עמודות, בטאבלט בשתי
עמודות ובטלפון בעמודה אחת.

## שאלות אפשריות בהגנה

### למה לא נתנו ל-jQuery לנהל את כל ה-DOM?

React מנהל את ה-DOM באמצעות state ו-Virtual DOM. שינוי מבני ישיר באמצעות
jQuery עלול לגרום לכך ש-React והמסך לא יהיו מסונכרנים. לכן השתמשנו ב-jQuery
ל-Ajax ולשינוי מחלקות CSS בתוך אזור מוגדר בלבד.

### איך נשלח הטוקן?

לפני כל בקשה השירות קורא את הטוקן מ-`localStorage`. אם קיים טוקן, הוא נוסף
לכותרת `Authorization` בפורמט `Bearer token`.

### מה ההבדל בין GET לבין POST או PATCH בשירות?

ב-GET הפרמטרים נשלחים כחלק משורת הכתובת. בבקשות שמשנות מידע הגוף מומר
למחרוזת JSON, ו-`contentType` מוגדר כ-`application/json`.

### כיצד מטופלת שגיאה?

ה-callback בשם `fail` יוצר אובייקט Error. אם השרת החזיר הודעה, היא נשמרת
ב-`error.response.data.message`, וה-View מציג אותה למשתמש.
