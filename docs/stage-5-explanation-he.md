# שלב 5 — צ׳אט בזמן אמת עם Socket.io

## מה נוסף?

בשלב זה נוספה מערכת צ׳אט בין לקוחות לבעלי עסקים. ההודעות עוברות בזמן אמת
באמצעות Socket.io ונשמרות ב־MongoDB, כך שהיסטוריית השיחה נשארת גם אחרי רענון
הדף או התחברות מחדש.

## מודל Message

- `sender` — המשתמשת ששלחה את ההודעה.
- `recipient` — המשתמשת שקיבלה אותה.
- `content` — תוכן באורך של עד 1,000 תווים.
- `readAt` — מועד קריאת ההודעה.
- `createdAt` ו־`updatedAt` — נוצרים אוטומטית על ידי Mongoose.

המודל תומך בכל הפעולות הנדרשות:

- Create — שליחה באמצעות אירוע Socket.io.
- List/Read — טעינת היסטוריה ורשימת שיחות באמצעות REST API.
- Search — חיפוש טקסט בתוך שיחה.
- Update — עריכת הודעה על ידי השולחת בלבד.
- Delete — מחיקת הודעה על ידי השולחת בלבד.

## אימות חיבור ה־Socket

בעת יצירת החיבור, הלקוח שולח את ה־JWT בשדה `auth`. השרת מאמת את הטוקן לפני
שהוא מאשר את החיבור. לאחר האימות, ה־Socket מצטרף לחדר פרטי בשם
`user:<userId>`.

כאשר נוצרת הודעה, השרת שולח אותה לשני חדרים בלבד: חדר השולחת וחדר המקבלת.
כך משתמשת אחרת אינה יכולה להאזין לשיחה שאינה שייכת לה.

## תהליך שליחת הודעה

1. המשתמשת כותבת הודעה ולוחצת Send.
2. React שולח אירוע `chat:send` עם מזהה המקבלת ותוכן ההודעה.
3. השרת בודק את המשתמשת, התפקידים, המקבלת ואורך התוכן.
4. ההודעה נשמרת ב־MongoDB.
5. האירוע `chat:message` נשלח מיד לשתי המשתתפות.
6. שני המסכים מתעדכנים ללא רענון הדף.

## שילוב REST ו־Socket.io

Socket.io משמש לפעולות שצריכות להגיע בזמן אמת. REST משמש לטעינת רשימת השיחות
וההיסטוריה, לחיפוש, לעריכה ולמחיקה. לאחר עריכה או מחיקה, השרת משדר אירוע
Socket.io נוסף כדי לסנכרן גם דפדפן אחר שפתוח באותו זמן.

## קבצים מרכזיים

- `server/src/models/Message.js` — סכמת ההודעה.
- `server/src/socket/chat.socket.js` — אימות ושליחה בזמן אמת.
- `server/src/controllers/message.controller.js` — היסטוריה, חיפוש, עריכה ומחיקה.
- `server/src/routes/message.routes.js` — נתיבי ה־REST והוולידציות.
- `client/src/services/chatSocket.js` — יצירת חיבור ה־Socket בצד הלקוח.
- `client/src/pages/ChatPage.jsx` — ממשק הצ׳אט.

## תשובה קצרה להגנה

הצ׳אט משתמש ב־Socket.io להעברת הודעות בזמן אמת וב־MongoDB לשמירה קבועה. ה־JWT
נבדק כבר בשלב ה־handshake, וכל משתמשת מצטרפת לחדר פרטי לפי המזהה שלה. השרת
מאמת שהשיחה מתקיימת בין לקוחה לבעלת עסק, שומר את ההודעה ומשדר אותה רק לשתי
המשתתפות.
